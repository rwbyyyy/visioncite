# VisionCite 简历材料

## 一、项目简介（66 字，含英文缩写与标点，可直接放进简历头部）

多模态文档问答：PDF/图片经版面分割与 OCR 切成区域，BM25 与 CLIP 双路检索、RRF 融合，答案附区域级证据框，证据不足时弃答。

技术栈：Python 3.10+、numpy、Pillow、pypdfium2、RapidOCR（可选）、CLIP（可选）、FastAPI、pytest。

---

## 二、STAR 式项目要点（三条）

**1. 版面分割到可点击的证据框**
- 背景/任务：文档问答的答案必须能指回原文某一小块区域；环境无 GPU、无 API key，还要能现场复现。
- 做法：自建 4 类模板 × 2 份 = 8 张图的合成语料、36 道题，标准答案与证据框由渲染坐标精确记录；实现 Otsu 二值化 → 递归 XY-cut → 表格线检测 → 区域装配的版面流水线，区域 bbox 直接作为引用坐标。
- 结果：layout 模式 AnswerAcc 1.00（24/24 已答可答题）、Cite-R 1.00、Cite-P 0.83（引用框与标准框 IoU ≥ 0.5 判命中）。
- 口径：自建 36 题合成基准、8 张图、CPU-only、无 CLIP、无 VLM。

**2. 零训练参数的双路检索与融合**
- 背景/任务：检索要同时覆盖金额、合同编号这类精确串和版式相似的图表；不引入需要标注数据训练、需要调权重的组件。
- 做法：中文按字 bigram 切词 + BM25（k1=1.5、b=0.75）做文本一路，CLIP 图像向量做视觉一路；两路按**名次**做 RRF（k=60）融合，再用 MMR（λ=0.7）去冗余；分数按 top-1 归一化，弃答阈值 0.35。
- 结果：单题问答延迟 p50 0.30 ms、p95 0.64 ms（36 题，CPU-only）。
- 口径：延迟含检索 + 抽取 + 校验，不含 OCR 与建索引；`page` / `hybrid` 两臂代码已就绪但本次未跑，因此不引用任何"视觉检索带来提升"的数字。

**3. 证据闭环与三级降级**
- 背景/任务：这类系统最大的产品风险是编造数字（金额、日期、比例）；OCR / CLIP / VLM 任一缺失都不应让服务不可用。
- 做法：三道校验（引用必须存在、答案数字必须逐字出现在被引证据、答案 token 覆盖证据 ≥ 0.5）＋ 三档弃答（无证据 / 校验失败 / 置信度 < 0.35）；无 OCR 退 PDF 文本层，无 CLIP 退单路检索，无 VLM 或 VLM 调用失败退 extractive。
- 结果：弃答判断准确率 0.83（30/36）、答题率 0.72（26/36）、ECE 0.19。
- 口径：同上；失败样本一并报告——4 道可答题因检索未命中被弃答，2 道不可答题被误答（置信度 0.44）。

## 三、可展开讲的三个亮点

**亮点 1：版面分析每一步都能画出来、都能单测**
- Otsu：遍历 256 个阈值取类间方差最大，实现用直方图 + `cumsum`，复杂度 O(256 + 像素数)；能现场推 `σ_b² = w0·w1·(μ0-μ1)²` 与它的等价形式 `(μ_T·w0 - μ0)²/(w0(1-w0))`。
- XY-cut：行/列投影找空白带，交替递归，切不动就换轴；同层子区域不重叠，所以每层代价 ≤ 页面像素数，总复杂度 O(D·N)，D=6。
- 每一步都有性质断言而不是快照：黑白两峰图阈值必须落在中间、全白页返回空列表、深度上限生效、高重叠块必须合并（`tests/test_layout.py`）。

**亮点 2：检索侧零训练参数，每个公式都能手推**
- 为什么不用分数加权：BM25 分数无上界、余弦在 [-1,1]，直接相加等于让 BM25 独占；RRF 只看名次，对尺度免疫，且没有可训练参数。
- 中文为什么用 bigram：不要词典、未登录词友好、对 OCR 错字容忍；代价是索引约为字数 1 倍、产生无意义 bigram，靠 IDF 自动降权虚词。
- MMR 在这里还有一个隐性作用：同一区域切出的多个块共享同一个 CLIP 向量，冗余度恒为 1，设计上会被 MMR 压掉，避免三条几乎一样的证据。

**亮点 3：把"不知道"做成一等公民**
- 校验、弃答、校准三层串起来：`verify` 判"有没有据"，`abstain` 判"该不该答"，`ECE` 判"置信度说得准不准"，报告里逐样本可复核。
- 降级不是隐藏的失败，而是可观测的能力开关：`/health` 报实际使用的 OCR / 视觉后端，日志打印 `vectors=on/off`，前端把后端名字显示在上传结果里。
- 工程结构上，路由层只做"校验输入 / 调用用例 / 翻译异常"，业务全在 pipeline 与 answer，因此可以用假 OCR 注入跑完全部离线测试。

## 四、两个必须主动说的局限

**局限 1：基准是合成的、规模小，CI 已经退化**
- 4 类模板 × 2 份、36 题，可答 28；实际作答 24 条时 bootstrap 95% CI 退化成 [1.00, 1.00]，没有统计分辨力。
- 证据框由渲染坐标精确得到，引用 IoU 命中比真实扫描件乐观；无线表、倾斜扫描、真实票据、多栏混排都没覆盖。
- 因此只能说"在这个自建小基准上"，不能推广到线上效果。

**局限 2：关键能力未闭环，且有一处指标瑕疵**
- VLM 路径没有在真实厂商端点上验证过（代码注释里自述），只有协议实现与失败回退。
- 本次报告只有 layout 一臂，CLIP 未启用；表格行文本有丢失（"合计"行只剩数字 15944.40），导致 4 道可答题弃答、答题率停在 0.72。
- AnswerAcc 1.00 与 EM 0.00、F1 0.40 并存：抽取式返回整句，粒度问题未解决；`min_citation_score` 定义了但没接线，属于死配置。

## 六、表达纪律

- 所有数字必须带口径：语料规模、模式、是否 CPU-only、是否含 OCR、IoU 阈值。
- 讲成绩时同时讲失败样本（4 题弃答、2 题误答），比只报 1.00 可信。
- 避免：笼统的"效果很好 / 提升明显"、没有口径的百分比、把合成基准的成绩说成线上效果、把"代码写了但没跑"说成"已验证"。
- 被问到"为什么只有 layout"：直接答"另两臂代码已就绪，这次时间盒内没跑，所以不引用它们的数字"。
