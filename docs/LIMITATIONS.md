# 已知限制

这份清单是刻意维护的：**能说清楚自己哪里不行，才说明知道自己在做什么**。
面试时被问"你这个方案的边界在哪"，直接照这份文件讲。

## 数据与评测

1. **评测语料是程序合成的**。干净背景、规整排版、无手写、无倾斜、无印章遮挡。
   真实扫描件（发票、合同、病历）的难度显著更高，数字不能直接外推。
2. **样本量小**：36 题。bootstrap 95% 区间会很宽，甚至退化（全对时区间为 [1,1]），
   因此不宣称"统计显著优于某方法"。
3. 没有人工盲评，也没有第二标注者；"标准答案"由模板决定，不涉及人类判断。

## 版面与 OCR

4. **表格只支持有可见框线的**。三线表、无线表、跨页表检测不到；
   多张小表同页时可能被包成一张大表（`layout/table.py` 用整页投影）。
5. **XY-cut 对多栏不留白、倾斜扫描、背景噪点敏感**；倾斜超过约 1° 时投影会断开。
6. OCR 依赖 `rapidocr-onnxruntime`；未安装时退化为"仅 PDF 文本层"，
   图片类文档将没有文本可检索（服务仍可用，只是答不出）。
7. 中文按字 bigram 分词，没有停用词表，虚词靠 BM25 的 IDF 自然降权；
   对"的/了"极多的口语文档会引入噪声。

## 检索与作答

8. **CLIP 不擅长读小字**。它对"这是一张柱状图"敏感，对"发票金额是 1286.40"基本无能为力。
   因此视觉一路只做召回，不做答案依据；纯文本题上视觉一路带来的增量有限。
9. `index/retrieve.py` 的 MMR 把**未归一化的 RRF 分数**（约 0.03 量级）与
   `[0,1]` 的余弦相似度混合，量纲不一致会让多样性项主导排序。
   这是已知缺陷，`docs/EXERCISES.md` 练习 9 要求你修掉它并做 A/B。
10. 抽取式答案只能摘句，不能跨段归纳、不能做算术（"两页金额之差"答不了）。
11. 弃答阈值（0.35）是手调的，没有做阈值扫描；可能"少答换准确"，
    也可能在简单题上误弃答。

## 工程

12. 文档只存在进程内存里（`app.state.documents`），重启即丢；
    没有持久化索引、没有并发控制、没有鉴权。
13. `perceptual_hash` / `hash_distance` 已实现但**没有接入去重主链路**；
    `count_pages` 同样未被调用。
14. VLM 适配器按 OpenAI 兼容协议实现，但**没有在真实厂商端点上验证过**；
    仓库运行环境没有 API key。
15. Dockerfile 未在本机构建验证（开发机没有 Docker）。
16. 置信度公式是启发式的，实测 ECE 偏高（过自信），未做校准。
